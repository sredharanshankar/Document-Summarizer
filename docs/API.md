# API Documentation

Base URL (local dev): `http://localhost:8000`
Interactive docs (auto-generated by FastAPI): `http://localhost:8000/docs`

All responses are JSON. All errors follow the same shape:

```json
{ "error": "<machine-readable code>", "message": "<user-facing text>" }
```

No endpoint ever returns a Python traceback or raw exception message.

---

## `GET /api/health`

Health check.

**Response `200`**
```json
{ "status": "ok" }
```

---

## `POST /api/documents/analyze`

Upload a document and start analysis. Processing runs in the background;
this endpoint returns immediately with a job ID to poll.

**Request:** `multipart/form-data`

| Field | Type | Required | Notes |
|---|---|---|---|
| `file` | file | yes | PDF, JPG, JPEG, or PNG. Max size per `MAX_FILE_SIZE` (default 10 MB). |
| `summary_length` | string | no | `short` \| `medium` \| `long`. Default `medium`. |

**Response `202 Accepted`**
```json
{ "job_id": "3f2e...c9", "status": "processing" }
```

**Errors**

| Status | `error` | When |
|---|---|---|
| 400 | `unsupported_file_type` | Extension isn't `.pdf`/`.jpg`/`.jpeg`/`.png` |
| 400 | `empty_file` | Zero-byte upload |
| 400 | `file_too_large` | Exceeds `MAX_FILE_SIZE` |
| 400 | `corrupted_file` | File content doesn't match its claimed extension (magic-byte mismatch), e.g. a `.txt` renamed to `.pdf`, or a PDF PyMuPDF can't open, or a password-protected PDF |

## `GET /api/documents/status/{job_id}`

Poll a job's status. Intended to be called every ~1-2 seconds while
`status` is `"processing"`.

**Response `200`**
```json
{
  "job_id": "3f2e...c9",
  "status": "processing",
  "stage": "summarizing",
  "filename": "report.pdf",
  "created_at": "2026-08-23T10:15:00Z",
  "result": null,
  "error": null
}
```

`status` is one of `processing` \| `completed` \| `failed`.
`stage` is one of `queued` \| `validating` \| `extracting` \| `ocr` \|
`cleaning` \| `summarizing` \| `done` - `ocr` only appears for scanned
PDFs/images; text-based PDFs skip it.

**When `status` is `"completed"`**, `result` is populated:

```json
{
  "job_id": "3f2e...c9",
  "status": "completed",
  "stage": "done",
  "filename": "report.pdf",
  "created_at": "2026-08-23T10:15:00Z",
  "result": {
    "metadata": {
      "filename": "report.pdf",
      "file_type": "pdf",
      "page_count": 12,
      "word_count": 8420,
      "used_ocr": false,
      "processing_duration_ms": 4210
    },
    "summary": "...",
    "summary_length": "medium",
    "key_points": ["...", "..."],
    "main_ideas": ["...", "..."],
    "improvement_suggestions": ["...", "..."],
    "ai_provider": "groq"
  },
  "error": null
}
```

`ai_provider` is `"groq"` or `"fallback"`, reflecting which path actually
ran for this job.

**When `status` is `"failed"`**, `error` is populated:

```json
{
  "status": "failed",
  "error": {
    "error": "empty_text",
    "message": "We couldn't extract readable text from this document. Please try a clearer image or a higher-quality scanned PDF."
  }
}
```

Possible `error.error` values at this stage: `ocr_failure`, `empty_text`,
`processing_error` (e.g. OCR disabled but required), `ai_provider_error`,
`ai_timeout`, `ai_rate_limit`, `internal_error`.

**Errors**

| Status | `error` | When |
|---|---|---|
| 404 | `not_found` | Unknown or expired job ID |

## `POST /api/documents/summarize`

Regenerate just the summary for a completed job at a different length,
without re-running extraction/OCR. Key points, main ideas, and improvement
suggestions are unaffected (they don't depend on summary length).

**Request:** `application/json`
```json
{ "job_id": "3f2e...c9", "summary_length": "long" }
```

**Response `200`**
```json
{ "summary": "...", "summary_length": "long" }
```

**Errors**

| Status | `error` | When |
|---|---|---|
| 404 | `not_found` | Unknown job ID |
| 422 | `processing_error` | Job exists but hasn't finished extraction yet |
| 502 | `ai_provider_error` | AI call failed or returned malformed output |
| 504 | `ai_timeout` | AI request timed out (after one retry) |
| 429 | `ai_rate_limit` | AI provider rate-limited the request |

## `POST /api/documents/ask`

Ask a free-form question about a completed document. Answers are grounded
in the document's own text - with Groq configured, the model is
instructed to say so explicitly rather than guess if the document doesn't
contain the answer; the fallback provider does literal keyword-overlap
sentence matching and returns "The document doesn't seem to mention that"
when nothing matches.

**Multi-turn:** the server keeps the last 6 (question, answer) exchanges
per job and automatically includes them as conversation context, so a
follow-up question ("does that apply to everyone?") can be answered
without repeating context. This is entirely server-side - the request
shape below never changes, whether it's the first question or the tenth.

**Request:** `application/json`
```json
{ "job_id": "3f2e...c9", "question": "What is the notice period for leave requests?" }
```

**Response `200`**
```json
{ "answer": "Leave requests must be submitted at least two weeks in advance.", "ai_provider": "groq" }
```

**Errors**

| Status | `error` | When |
|---|---|---|
| 400 | `validation_error` | Question is blank, or over 2000 characters |
| 404 | `not_found` | Unknown job ID |
| 422 | `processing_error` | Job exists but hasn't finished processing yet |
| 502 | `ai_provider_error` | AI call failed or returned malformed output |
| 504 | `ai_timeout` | AI request timed out (after one retry) |
| 429 | `ai_rate_limit` | AI provider rate-limited the request |

## `POST /api/documents/compare`

Compare 2-5 already-completed documents (identified by job ID - no
re-upload needed). With Groq configured, the model produces a genuine
comparative analysis; the fallback provider compares each document's most
frequent keywords, reporting shared terms as similarities and each
document's distinctive terms as differences (index-based, not
filename-based, so two uploads that happen to share a filename compare
correctly).

**Request:** `application/json`
```json
{ "job_ids": ["3f2e...c9", "7a1b...44"] }
```

**Response `200`**
```json
{
  "documents": ["marketing-report.pdf", "engineering-report.pdf"],
  "comparison_summary": "Both documents are Q1 performance reports from different departments...",
  "similarities": ["Both are Q1 reports stating that delivery exceeded targets", "..."],
  "differences": ["marketing-report.pdf focuses on social media campaigns...", "..."],
  "ai_provider": "groq"
}
```

**Errors**

| Status | `error` | When |
|---|---|---|
| 400 | `validation_error` | Fewer than 2 or more than 5 job IDs given |
| 404 | `not_found` | One of the job IDs is unknown |
| 422 | `processing_error` | One of the jobs hasn't finished processing yet |
| 502 | `ai_provider_error` | AI call failed or returned malformed output |
| 504 | `ai_timeout` | AI request timed out (after one retry) |
| 429 | `ai_rate_limit` | AI provider rate-limited the request |
